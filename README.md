# C++ 算法竞赛题解与学习记录

这是我的个人算法竞赛仓库，主要记录算法学习、专题训练、日常刷题以及比赛过程中完成的 C++ 代码。

仓库中的内容来自长期的算法训练，而不是为了整理项目临时创建。代码覆盖基础算法、动态规划、数据结构、图论、数论、字符串、树上算法等多个方向，也包含来自不同 Online Judge 和竞赛平台的题目。

我希望通过这个仓库持续保存自己的算法积累，同时也能够比较直观地展示自己的算法基础、代码实现能力以及解决问题的经验。

## 这个仓库记录什么

这个仓库最主要记录三类内容。

### 1. 算法学习

学习一个新的算法或数据结构以后，通过实际题目完成理解、实现和应用，而不是只保存一份模板。

例如：

- ST 表不仅仅是写出倍增数组，还需要理解区间长度和循环边界；
- LCA 不只是记住模板，还需要掌握树的建图、深度维护和倍增关系；
- 最小生成树、并查集、LCA 等算法也可能出现在同一道综合题中。

### 2. 刷题与比赛

保留平时专题训练以及各类 Online Judge、算法比赛中完成的题目代码。

这些代码更多体现的是实际解题过程：

- 根据数据范围判断复杂度；
- 从题目中抽象算法模型；
- 选择合适的数据结构；
- 完成实现并处理边界情况；
- 对错误代码进行调试和修正。

### 3. 算法积累

随着题量增加，一些常见算法会逐渐形成自己熟悉的实现方式。相比直接复制一份所谓的"标准模板"，我更希望通过反复使用，把算法实现真正变成自己的东西。

## 代码特点

仓库中的代码主要使用 C++ 编写，并保留比较明显的算法竞赛风格。

竞赛代码通常更关注：

- 正确性；
- 时间复杂度和空间复杂度；
- 实现速度；
- 调试效率；
- 常用代码的复用。

因此，这里的代码不会刻意按照大型工程项目的方式进行封装。不同阶段的代码在命名、注释和写法上也可能存在差异，我会保留这些内容，因为它们本身也是学习过程的一部分。

## 关于算法竞赛

长期做算法题对我最大的帮助，不只是记住了多少个算法。更重要的是逐渐形成下面几种能力：

- **问题建模**：面对一道陌生题目，能够逐步判断它更接近图、树、区间、状态、字符串还是数学问题。
- **复杂度意识**：根据数据范围判断某种算法是否可行，而不是先写完代码再考虑会不会超时。
- **代码实现**：把一个抽象算法稳定地转化为 C++ 实现，并正确处理各种边界条件。
- **调试能力**：能够根据 WA、TLE、MLE、RE 等结果快速排查思路、复杂度和代码实现中的问题。

这些能力也是我持续进行算法训练的主要原因。
